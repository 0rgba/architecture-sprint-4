### Мотивация

Мониторинги позволят быстро видеть проблемы, реагировать на них и устранять их, что повысит удовлетворённость пользователей и сократит затраты

### Выбор подхода к мониторингу

Для MES API (в первую очередь - подсчёт цены изделия) - USE, т.к. время обсчёта модели зависит от самой модели, поэтому RPS и Duration могут плавать и это нормально, но важно уметь скейлить сервис под текущую нагрузку

Для остальных сервисов подойдёт RED, т.к. он хорошо подходит для веб-сервисов и API

### Что и где отслеживать

- Стандартные метрики нагрузки (процессор, память, диск, сеть), везде. Для скейлинга большинства сервисов.
- Особое внимание на насыщенность и утилизацию в MES API для просчёта моделей. Для скейлинга сервиса подсчёта цены изделий. 
- Метрики на логи медленных запросов в базе. Для своевременого обнаружения медленных запросов и работы с ними
- Бизнес-метрики на конверсию. Для того, чтобы быстро обнаруживать проблемы в новых релизах, если они портят конверсию
- Бизнес-метрики на время нахождения заказов в определённом статусе. Для отслеживания зависших заказов без жалоб пользователей
