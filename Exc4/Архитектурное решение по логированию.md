### Мотивация

Добавление логгирования позволит быстрее расследовать и решать инциденты, тем самым сэкономить время разработки, а так же снизить даунтайм и повысить удовлетворённость пользователей

Какие метрики позволит улучшить:

- Время разбора инцидентов
- Удовлетворённость клиентов
- Снижение даунтайма при инцидентах

### Предлагаемое решение

Сделать систему просмотра логов доступной только из внутренней сети только для пользователей, которым она нужна для работы (служба поддержки, дежурный разработкик).
Чувствительные данные при этом анонимизируются в логах (частично заменяются звёздочками, заменяются полностью на вымышленные данные, сокращаются).
Логи с прода хранятся достаточное для разбора проблем время (обычно не превышает неделю) с возможностью выгрузки интересующих кусков для долговременного хранения.

Логгировать везде стандартный набор данных (время, идентификатор покупателя, номер заказа, название сервиса), а так же информацию, на основании которой в коде принимаются решения (if/switch), либо просто факты принимаемых решений, если эта информация чувствительная.

Нужен алертинг на повышение уровня ошибок, появление новых ошибок, а так же внезапный рост существующих логов других уровней.

Список логов с уровнем INFO:
- Начало обработки запроса на стороне сервиса
- Окончание обработки запроса на стороне сервиса
- Отправка запроса в другой сервис
- Получение ответа из другого сервиса
- Изменение статуса заказа

Логи с другим уровнем:

- ERROR: Получение ошибки при запросе в другой сервис
- FATAL: Отказ в работе критичных частей (например, сервис авторизации или базы данных)
- WARN: Попытки перебора паролей
